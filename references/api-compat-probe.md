# 接口兼容性探测

## 为什么需要

导入页及其使用的服务端接口不是公开承诺稳定的 API。页面文案、批量限制、运动类型矩阵、字段结构与错误码都可能随版本变化。仓库中的「最近核验」只描述某一次观察，不能替代使用前的检查。

## 主动询问（强制流程）

`SKILL.md` 规定：在执行迁移流程前，必须先询问使用者是否进行接口兼容性探测，并说明每种方式的步骤与影响；未经确认，不执行会向账号写入记录的操作。命令行用户可直接运行：

```bash
python scripts/check_api_compat.py
```

脚本会列出三种选项、输出所选方式的步骤清单，并把选择记录到本地 `.api_compat_choice.json`（该文件不进入版本库）。

| 选项 | 是否写入账号 | 内容 |
|---|---|---|
| 1 只读检查 | 否 | 读取导入页当前文案（支持格式与类型、单批/单文件限制、最早可导入日期），以及服务端返回结构的字段名；与文档记录比对 |
| 2 合成哨兵探测 | 是 | 生成不含真实个人信息的合成 FIT，导入后回读服务端，比对距离/时长/分段/统计字段与重复导入行为 |
| 3 跳过 | 否 | 直接使用仓库现有结论，接受其可能过期 |

## 方式 1：只读检查的步骤

1. 打开导入页，记录页面展示的格式、支持类型、单批文件数、单文件体积、最早可导入日期等文案。
2. 在已登录页面上下文读取 `activityRecords` 返回的一条记录，记录 `activitySummary` 顶层键、`dataSummary` 的 `dataTypeName` 集合、`sectionSummary` 单段键、`performanceSummary` 与 `paceSummary` 的键名。
3. 与 `references/huawei-limits.md`、`references/field-reference.md` 的记录比对，输出差异清单。
4. 不导入任何文件，不产生记录。

## 方式 2：合成哨兵探测的步骤

1. 生成两份**同一开始时间、同一运动类型、内容不同**的合成 FIT（例如 2 km / 600 s / 2 段 与 3 km / 900 s / 3 段），不含真实轨迹、账号标识或健康数据。
2. 逐份导入，每次导入后回读服务端记录。
3. 判据：

| 观察项 | 覆盖生效 | 跳过 | 追加 |
|---|---|---|---|
| 距离、时长、分段数 | 变为第二份 | 保持第一份 | — |
| 记录条数 | 1（id 不变） | 1 | 2 |
| 统计字段集合 | 随采样点变化 | 不变 | — |

4. 记录服务端返回的字段结构，更新本地核验记录并注明日期。

**影响**：哨兵导入后是账号内的一条真实运动记录。仓库不提供删除能力（删除接口未开放），需使用者在华为运动健康 App 内自行删除。执行前须再次确认。

## 最近一次核验（2026-11-18，合成数据）

| 项目 | 观察结果 |
|---|---|
| 页面文案 | FIT 支持跑步/骑行/游泳/步行/铁三/力量训练；TCX 仅跑步/骑行；最多 50 个文件、单个 ≤5 MB |
| 重复导入 | 同一开始时间 + 运动类型，第二份合成 FIT 覆盖第一份；距离 2000→3000 m、时长 600→900 s、分段 2→3 段，记录 id 不变，未观察到新增记录 |
| 派生统计 | 哨兵未写 `total_cycles`，服务端按逐点步频计算步数；说明部分统计由服务端按采样点生成 |
| `activitySummary` 顶层键 | `paceSummary`、`performanceSummary`、`dataSummary`、`sectionSummary` |
| 统计类型 | 心率、距离、步频、海拔、卡路里、步数、运动心率、速度、步幅等 `dataTypeName` |
| 分段单段键 | `sectionNum`、`sectionTime`、`startTime`、`endTime`、`sectionDataList` |

该记录来自单个账号、单个时间点、单条合成记录，**不构成对接口行为、稳定性或未来版本的保证**。字段含义与官方链接见 `references/field-reference.md`。
