# 操作要点

本文汇总执行迁移时容易踩到的工程要点，供 `SKILL.md` 的流程与 `examples/end-to-end.md` 的示例配套使用。每条都是通用操作建议，不构成对平台行为的保证；结论的时间基准见 `references/current-status.md`。

## 1 顺序：先看实时状态，再动文件

1. 运行 `scripts/check_api_compat.py`，确认是否做接口兼容性探测及选择哪种方式。
2. 阅读 `references/current-status.md`，确认页面文案、批量限制、字段结构与写入语义的核验时间。
3. 差异以**实时探测结果**为准。仓库中的类型矩阵、错误码表、字段清单都是某次观察，不能替代使用前的检查。
4. 未经确认，不执行会写入账号的探测。

## 2 环境与登录

- 在仓库根目录执行全部命令；脚本按相对路径互相引用，换目录会找不到模块。
- `check_environment.py` 为 `partial` 时，转换/编码/自检仍可用，导入与核验需走人工降级路径。
- 首次导入会打开浏览器并停在华为账号登录页，需手动完成一次登录；登录态保存在本地浏览器配置目录，不保存账号密码或验证码。
- 出现验证码、安全验证、「操作过于频繁」时立即停止自动化，改为手动完成本次导入。
- 页面会显示可导入的最早日期；早于该日期的记录会被拒（`activity.time.exceed`）。不要写死日期。

## 3 编码口径

| 项目 | 要点 |
|---|---|
| 分段 | 默认 `--lap-mode auto`：跑步按公里分段，其它类型零分段。非跑步带分段会被拒（`This activityType is not support section.`） |
| 时间轴 | `record` / `lap` 时间戳必须落在 `session` 区间内；`lap` 时长必须等于其时间戳跨度，不能按比例缩放 |
| 时长 | `total_elapsed_time` 是墙钟跨度，`total_timer_time` 是有效运动时长，两者不要混用 |
| 步频 | 逐点 `cadence` 按 rpm 写入；只有存在逐点步频序列时才写 `session` / `lap` 的步频汇总，否则会触发 `Mismatched value count` |
| 距离 | 末条 `record.distance` 应与 `session.total_distance` 一致；单位差 10 倍会被判为异常 |
| 体积 | 单文件 ≤ 5 MB；本包不含抽稀工具，超限需降低采样频率后重新转换编码 |
| 不造数据 | 源数据没有的心率、步频、GPS 不写、不插值；允许按「总里程 + 时间轴」派生距离与速度时，需在转换输出中标注，`--no-derive` 可关闭 |

## 4 批量通道

- 导入页文件输入是 `multiple`，页面文案写明**一次最多 50 个文件**，单文件 ≤ 5 MB。
- `huawei_upload.py --batch` 默认 10，可用 `--batch 50` 一次提交整批，减少提交次数（上限 50）。
- 批量结果弹窗**只给汇总，不指出具体失败文件**。因此：
  1. 失败批先整批复传一次，排除偶发失败；
  2. 仍失败时再回退到逐文件提交定位；
  3. 不要对同一批反复自动重试。
- 每批结束后脚本会重新读取服务端记录判断是否入库；页面「成功」不作为判据。
- `--dry-run` 只读服务端、列出待传清单，不上传任何文件，适合正式执行前过一遍。
- `--workouts` 是必填项：缺了它无法判断哪些记录已入库，脚本会拒绝运行。

## 5 幂等与重传

- 最近一次核验：同一开始时间与运动类型的再次导入按**整条覆盖**处理，未观察到新增记录。因此不必先清空账号再重传。
- 该行为不是官方承诺，流程仍保持「先查后传、失败不自动重传」。
- 派生统计（步数、心率区间、最大速度等）由服务端按采样点自算；**采样点不变的重传不会带来可见变化**。要改结果，先改源数据或逐点明细，再重新编码。
- 页面提示成功但服务端没有记录，属于静默丢弃，常见于极短记录、只有汇总没有逐点细节、距离为 0 且无轨迹。反复重传不改善。
- 核验报「无法确认」（同一分钟多条且时长都对不上）时，先人工核对，不要直接重跑。

## 6 服务端字段与展示边界

- `activitySummary` 是统计结构，不是时间序列；曲线类展示由客户端按采集器采样点绘制，不是记录字段。
- 导入记录所属应用生成的采集器通道里没有逐点速度通道；往 FIT 里再加字段不会让速度曲线出现。
- 骑行记录保留速度的 avg / max，但通常只显示平均值；步行记录不保留步频/步幅统计；分段结构只在跑步类型上观察到。详见 `references/current-status.md`。
- 导入页原文写明：导入数据不计入运营统计、个人成就统计、周月年报统计与运动能力评估。

## 7 探针与清理

- 类型探针用 `scripts/make_probe.py` 生成，一次只传一个类型并立即核验，否则无法归因。
- 探针时间会挪到样本当天凌晨并逐个错开，避免与待导入记录撞在同一分钟。
- 探针导入后即成为账号内的真实记录；仓库不提供删除能力，需使用者在 App 内自行删除。
- 合成哨兵探测同理，执行前须确认写入账号的影响。

## 8 结果交付

- 通过条件：核验报告「缺失」0、「重复」0、「时长不一致」0；「无法确认」需人工确认。
- 平台限制导致无法导入的记录单独列清单，不并入成功数。
- 真实导出文件、FIT、登录态、核验报告与审计 JSON 都保存在本地，不应提交到公开仓库；提交 issue 或日志前检查轨迹、心率、账号与令牌。见 `references/security-privacy.md`。

## 9 失败定位顺序

文件结构（`fit_audit.py`）→ 平台限制（`huawei-limits.md` / 探针）→ 页面操作与批量弹窗 → 账号与登录（`setup-guide.md`）。错误码对照见 `references/troubleshooting.md`，核验口径见 `references/verification.md`。
