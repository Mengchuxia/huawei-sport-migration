# 华为导入页限制与类型矩阵

本文记录特定时间点的观察结果，最近核验：2026-11-18 01:02（只读），完整状态快照见 `references/current-status.md`。平台行为可能变化，不构成官方承诺；**执行前按 `references/api-compat-probe.md` 询问并复核，实时结果优先于本文**。

## 页面硬限制

| 项目 | 规则 |
|---|---|
| 格式 | FIT 或 TCX，二选一（页面上是单选按钮）；文件输入为 `multiple`，一次提交可带多个文件 |
| TCX 支持 | 仅跑步、骑行 |
| FIT 支持 | 页面文案列出跑步、骑行、游泳、步行、铁三、力量训练 |
| 单批文件数 | ≤ 50 |
| 单文件大小 | ≤ 5 MB |
| 导入后改类型 | 不支持，导入即定稿 |
| 重复导入 | 最近核验（2026-11-18）：同一开始时间与运动类型的再次导入按整条覆盖处理，未观察到新增记录；该行为非官方承诺，可能变化 |
| 账号地区 | 中国大陆账号；境外账号可能不可用 |
| 起始日期 | 页面会显示可导入的最早日期，以页面当时显示为准；本次只读核验时该日期变量渲染为空，不要写死 |
| 导入数据口径 | 页面原文：导入数据不计入运营相关统计、个人成就统计、周月年报统计与运动能力评估 |

| 运动 | 结果 | 说明 |
|---|---|---|
| 跑步 running | 可导入 | 支持按公里分段 |
| 步行 walking | 可导入 | 必须零 lap |
| 骑行 cycling | 可导入 | 必须零 lap |
| 力量训练 strength | 可导入 | 必须零 lap |
| 羽毛球 badminton | 可导入 | 必须零 lap，是扩展类型里少数可用的 |
| 游泳 swimming | 拒收 | 无卡路里报 `required dataType missing`，带卡路里报 `samplePoint dataType is not valid` |
| 乒乓球 pingpong | 拒收 | 解析层返回 `60002102`（不认运动码） |
| 电竞 e_sports | 拒收 | 同上 |
| 划船机 rowing_machine | 拒收 | 同上 |
| 攀岩 climbing | 拒收 | 同上 |

「可导入」指服务端出现对应记录，不只是弹窗提示成功。该矩阵为观察记录，不构成保证。

## 数据与展示边界（2026-11-18 01:02 只读核验）

导入通道按运动类型落库的字段覆盖有限，以下差异**不是「往 FIT 里再加字段」能解决的**：

| 运动类型 | 服务端保留 | 客户端常见表现 |
|---|---|---|
| 跑步 | 距离、速度、步数、步频/步幅统计、心率、分段 | 分段结构本次只在跑步类型上观察到 |
| 步行 | 距离、速度、步数、心率、卡路里 | 即使 FIT 写了逐点步频与汇总步频，服务端也不保留步频/步幅统计 |
| 骑行 | 距离、速度 avg/max、心率、卡路里 | 只显示平均速度，没有速度曲线；导入记录没有逐点速度采集通道 |
| 力量训练等 | 心率、卡路里 | 无距离、速度、分段 |

原因分两层：`activitySummary` 的 `dataSummary` 是统计点而不是时间序列；曲线类展示由客户端按采集器采样点绘制。官方「健走」「骑行」数据类型页列出的字段不等于导入记录一定会落库。字段结构与核验方式见 `references/current-status.md`、`references/field-reference.md`。

## 三类反馈要分清

1. **页面提示成功、服务端有记录** —— 真的成功
2. **页面提示成功、服务端没有记录** —— 静默丢弃，常见于极短记录或无有效细节的记录
3. **页面提示失败** —— 看错误码，见 `troubleshooting.md`

只信第 1 种。核验方法见 `verification.md`。

## 复测与接口探测

```bash
python scripts/make_probe.py --input workouts.json --out-dir probes
```

用一条合成记录生成只差运动类型的几个文件，逐个上传、逐个核验；一次只传一个类型，否则无法归因。

接口层面的复核（页面文案、服务端字段结构、重复导入语义）见 `references/api-compat-probe.md` 与 `references/current-status.md`；执行前应通过 `scripts/check_api_compat.py` 主动询问使用者是否探测，并说明各方式的影响。批量、重传与失败处理的工程要点见 `references/operational-notes.md`。

探针时间会被挪到样本当天凌晨并逐个错开，不会撞到待导入记录；但探针导入后就是真实记录，
本包删不掉，**测完在 App 里手动删除**。
