# 失败排查

先定位属于哪一层：文件结构 / 平台限制 / 页面操作 / 账号。

## 平台返回的错误

| 提示 | 含义 | 处理 |
|---|---|---|
| `60002102` | 解析层不认这个运动码 | 该类型平台不支持，见 `huawei-limits.md`；用探针复测确认 |
| `This activityType is not support section.` | 非跑步类型带了分段 | 对非跑步使用 `--lap-mode none`（默认 auto 已处理） |
| `Mismatched value count: continuous.steps.rate.statistics` | 只有步频汇总、没有逐点步频序列 | 不写 session/lap 的步频汇总，只保留逐点 `cadence` |
| `required dataType missing` | 缺少平台要求的汇总数据 | 常见于游泳；补齐卡路里等字段仍可能失败 |
| `samplePoint dataType is not valid` | 采样点里出现该类型不接受的字段 | 针对该类型减少逐点字段（位置/海拔/步频）后重试 |
| `Invalid section startTime` | 分段时间与时间戳不一致 | 检查 lap 时长是否等于时间戳跨度、是否落在 session 区间内 |
| `ActivityRecord.details.time does not match` | 明细时间超出汇总区间 | 同上，收拢时间轴 |
| `fitFailCode5` | 文件非法 | 用 `fit_audit.py` 复查结构，确认必需消息齐全 |
| `activity.file.nodata` | 文件没有有效数据 | 补采样点或汇总；只有时长的记录会被判无数据 |
| `activity.time.exceed` | 时间超出可导入范围 | 页面会显示最早可导入日期，早于该日期的记录无法导入 |
| `未识别的运动类型：other` | 源文件的运动码没映射上（佳明 `sport=0` 常见） | 转换时加 `--sport running` 之类的参数强制指定 |
| 文件超过 5 MB | 平台单文件上限 | 本包不含抽稀工具：降到更低采样频率后重新转换、编码 |

## 提示成功但 App 里看不到

不是「导入失败」，是「平台判定无效」：

- 极短记录（十几秒）
- 只有汇总、没有任何逐点细节
- 距离为 0 且无轨迹

处理：接受现实或补录，不要反复重传。最近一次核验显示同一开始时间与运动类型的重复导入按整条覆盖处理、未观察到新增记录（见 `current-status.md`），但覆盖不是修复手段：源数据不变时，重传不会改变服务端按采样点算出的结果。

## 能看到记录，但只有平均配速

配速曲线是拿逐点数据算出来的，缺了就只剩平均值。按这个顺序查：

1. **距离对不上**：运动详情里的总距离是实际的 10 倍（例如 21 km 显示 211 km），
   或分段变成几百段——逐点距离把「分米」当成了「米」。用当前版本的 `from_bridge.py`
   重新转换、重新编码；旧文件不要导入。
2. **源数据本来就没有逐秒细节**：`fit_audit.py` 会提示「逐点速度几乎恒定」。
   早期小米/华米记录常常只有总距离和心率，没有逐秒速度或逐点距离，
   只能按总里程线性铺开，速度自然是一条平线。这不是编码问题，任何转换都补不出来。
3. **配速被华为判为异常**：跑步快于 2 分/公里、骑行快于 50 秒/公里，平台会丢弃图表。
   自检里出现「存在快于 2 分/公里的配速」时先修数据，别上传。
4. **导入记录的落库口径**：`activitySummary` 存的是统计点，不是时间序列；曲线由客户端按采集器采样点绘制。
   即使 FIT 里逐点速度、逐点步频都齐全，导入记录也可能只显示平均值，或不保留步频统计。
   这与「再加字段」无关，见 `huawei-limits.md` 的「数据与展示边界」与 `current-status.md`。

已经导入且确认是第 1 种情况的记录，应先用当前版本的 `from_bridge.py` 重新转换、重新编码，
再导入同一开始时间与运动类型的文件。最近一次核验显示这种重复导入按整条覆盖处理、未观察到新增记录；
但该行为并非官方承诺，导入后仍须以服务端记录核验。采样点不变的重传不会带来可见变化。

## 页面操作层

| 现象 | 原因 | 处理 |
|---|---|---|
| 上传后按钮无反应 | 文件未真正挂到列表 | 先清空列表再选文件，确认列表条目数等于文件数 |
| 结果弹窗关不掉，下一批读到旧数字 | 关闭按钮是容器不是按钮 | 点弹窗底部「确认」，并确认弹窗已隐藏 |
| 读到的数字总是同一条 | 弹窗叠加，取到了第一个 | 取最后一个可见弹窗 |
| 弹窗显示成功但服务端没有 | 静默丢弃 | 以服务端核验为准，见 `verification.md` |
| 批量提交后个别文件失败 | 批量结果弹窗只给汇总，不指出失败文件 | 先整批复传一次排除偶发；仍失败再回退逐文件定位，见 `operational-notes.md` |

## 账号与登录

| 现象 | 处理 |
|---|---|
| 页面跳到华为账号登录 | 在自动化打开的浏览器窗口里手动登录，登录态会保存 |
| 登录后仍提示未登录 | 关掉浏览器重开；确认访问的是导入页而不是缓存页 |
| 提示账号不支持 | 仅中国大陆账号可用 |
| 反复要求验证 | 停止自动化，手动完成本次导入 |
